Key entities (concise schema sketch)

Repository       (id, owner, name, default_branch, html_url)
GithubUser       (login, avatar_url, name?)                      # denormalized

PullRequest      (id, repo_fk, number, title, body, state, draft,
                  head_ref, head_sha, base_ref, base_sha,
                  author_login, created_at, updated_at, closed_at?, merged_at?,
                  mergeable_state, html_url, etag?, last_synced_at)

DiffFile         (id, pr_fk, path, previous_path?, status,
                  additions, deletions, sha, patch_truncated, patch?)

Review           (id, pr_fk, github_id, state, body, author_login,
                  submitted_at?, etag?)
                  # state: PENDING | COMMENTED | APPROVED | CHANGES_REQUESTED | DISMISSED

Comment          (id, pr_fk, review_fk?, parent_fk?, github_id, kind,
                  body, author_login, path?, position?, line?, side?,
                  created_at, updated_at, deleted_at?, etag?)
                  # kind: issue | review

Thread           (id, pr_fk, root_comment_fk, github_thread_id?,
                  resolved, resolved_by?, resolved_at?)

CheckRun         (id, pr_fk, head_sha, github_id, name, status, conclusion?,
                  started_at, completed_at?, details_url?, etag?)

WorkflowRun      (id, pr_fk, head_sha, github_id, name, status, conclusion?,
                  html_url, etag?)

Workspace        (id, pr_fk, mode, worktree_path, created_at,
                  archived_at?, last_active_at, webhook_subscription_id?)
                  # mode: author | reviewer

Storyline        (workspace_fk, file_path_in_branch, sha_when_loaded, raw_content)
StorylineFile    (storyline_fk, diff_file_path, order_index, intro_text?)

AIAnalysisDoc    (workspace_fk, ingested_at, source_label?, raw_content)
AIAnalysisFile   (ai_doc_fk, diff_file_path, sections_json)

LocalAnnotation  (workspace_fk, diff_file_path, line?, body, created_at)
                  # private, never syncs

DraftReview      (workspace_fk, state, body?, status)
                  # state: COMMENT | APPROVE | REQUEST_CHANGES
                  # status: building | submitting | submitted (→ Review row)
DraftComment     (draft_review_fk?, diff_file_path?, position?, line?, side?,
                  body, reply_to_comment_fk?)

Outbox           (id UUIDv7, workspace_fk, action_type, payload_json, status,
                  attempt_count, last_error?, github_response_ref?,
                  precondition_etag?, enqueued_at, resolved_at?)

SyncEvent        (id, workspace_fk?, direction, event_type, payload_json,
                  delivery_id? UNIQUE, outbox_fk?, occurred_at)

Modeling notes

  • Two comment kinds in one table. kind=issue|review. Issue comments have null path/position/line. Review comments are line-anchored and link to a Review.
  • Threads explicit. Github GraphQL exposes them; REST does not. Backend reconstructs threads from parent-fk chains; resolved state is fetched via GraphQL.
  • ETags everywhere mirror rows are mutable. Captured at fetch, sent as If-Match on outbound edits.
  • Drafts are separate from published. Once a DraftReview submits successfully, a Review + Comment rows are created in the mirror by the worker (from github's response). DraftReview rows are NOT mutated into Reviews — they stay as audit trail of intent.
  • LocalAnnotation never publishes. Schema-enforced: no outbox action_type writes from it.
  • Storyline is parsed cache. Truth = the json file at head_sha:.local-review/storyline.json. Cache invalidated when head_sha changes.
  • AI-doc is opaque-ish. Backend parses known top-level structure (per-file blocks) but stores raw markdown/json for re-render.
  • GithubUser denormalized. Per-row author_login + lookup table for display data only. Avoids re-fetch on every render.
  • SyncEvent.delivery_id UNIQUE → inbound webhook dedup, no compound primary key needed.

What this model does NOT include (intentional)

  • Full file content snapshots — only the patch (diff hunks). File content fetched on demand via git show head_sha:path through git ops.
  • Per-line blame — not needed for review storyline.
  • Per-PR settings table — workspace_id row carries the settings.
  • Inter-workspace links — each workspace is independent. Cross-PR review (e.g., a stack) is out of scope for v1.
  • Branch-protection / CODEOWNERS mirroring — fetched on demand at merge time, not mirrored.
