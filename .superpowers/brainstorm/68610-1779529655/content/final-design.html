Final data model (10 tables)

User
  id, github_login UNIQUE, github_user_id, display_name?, avatar_url?,
  created_at, last_login_at

UserRepoPermission                                              # cache, written but not gated in v1
  id, user_fk, repo_owner, repo_name, level, fetched_at, expires_at
  UNIQUE (user_fk, repo_owner, repo_name)

Workspace
  id, repo_owner, repo_name, pr_number,
  created_by_user_fk, created_at, archived_at?, last_active_at
  UNIQUE (repo_owner, repo_name, pr_number)                     # one workspace per PR

Storyline
  workspace_fk PRIMARY,
  raw_json, etag (uuid, bumped per write),
  updated_at, updated_by_user_fk

StorylineFile
  id, storyline_fk, diff_file_path, order_index, intro_text?
  UNIQUE (storyline_fk, diff_file_path)

IntroComment
  id, storyline_file_fk, user_fk, parent_fk?,
  body, created_at, updated_at, deleted_at?,
  resolved_by_user_fk?, resolved_at?

AIAnalysisDoc
  id, workspace_fk UNIQUE, raw_content, ingested_at,
  ingested_by_user_fk, source_label?

AIAnalysisFile
  id, ai_doc_fk, diff_file_path, sections_json
  UNIQUE (ai_doc_fk, diff_file_path)

DraftReview                                                     # singleton per (workspace, user)
  workspace_fk + user_fk PRIMARY,
  body?, event ENUM(COMMENT, APPROVE, REQUEST_CHANGES),
  created_at, updated_at

DraftComment
  id, workspace_fk, user_fk, draft_review_fk?,
  kind ENUM(issue, review),
  diff_file_path?, position?, line?, side?,
  body, parent_comment_github_id?,
  created_at, updated_at

Four representative request flows

A · CREATE WORKSPACE  (e.g., via `local-review import {owner}/{repo}#{n}`)
  client → POST /api/workspaces { repo_owner, repo_name, pr_number }
        → backend: verify PR exists on github (admin PAT GET /repos/.../pulls/{n})
        → INSERT Workspace
        → if current user is PR author: INSERT empty Storyline row + StorylineFile rows
          mirrored from current PR diff file list (just paths, no patches stored)
        → respond 201 + workspace metadata


B · LOAD WORKSPACE FOR REVIEWING
  client → GET /api/workspaces/{id}                  (returns metadata + storyline)
  client → GET /api/workspaces/{id}/pr                (proxy: github PR object)
  client → GET /api/workspaces/{id}/files              (proxy: github diff files)
  client → GET /api/workspaces/{id}/comments           (proxy: combined comments)
  client → GET /api/workspaces/{id}/checks             (proxy: check runs)
  client → GET /api/workspaces/{id}/threads            (proxy: resolved state via GraphQL)
  client → GET /api/workspaces/{id}/drafts             (my pending drafts)
        UI renders storyline + ordered files + intros + IntroComments + github data


C · POST A LINE COMMENT  (single, immediate)
  client → POST /api/workspaces/{id}/drafts { kind: review, path, line, body }
        → INSERT DraftComment
  client → POST /api/drafts/{draft_id}/publish
        → backend: POST /repos/.../pulls/{n}/comments  via PyGithub
        → on success: DELETE DraftComment row
        → respond with github comment object


D · EDIT STORYLINE  (author only)
  client → GET /api/workspaces/{id}/storyline          (returns json + etag header)
  client → PUT /api/workspaces/{id}/storyline
           If-Match: 
           body: updated json
        → backend: check user.github_login == workspace.pr.author_login on github
        → check etag match; if mismatch → 409
        → UPDATE Storyline + replace StorylineFile rows
        → bump etag (uuid)
        → respond 200 + new etag

What is intentionally NOT in v1

  • SSE / realtime push for any data (refresh button or refetch on focus)
  • Github webhook ingress (no tunnel needed)
  • Cache layer for github reads (always fresh)
  • Mirror tables for any github primitive
  • Outbox / worker / async tasks
  • django-q dependency
  • LocalAnnotation feature
  • Cross-PR / stacked PR navigation
  • Fine-grained authz (permissive in v1; storyline-edit identity check is the one rule)

Tech debt parked (with rationale)

  • Admin PAT — all github actions appear authored by the PAT owner. Replace with per-user OAuth tokens (App or OAuth App) before any real deployment.
  • No live updates — collaborative editing of storyline by author and concurrent viewing by reviewers needs SSE eventually.
  • No github read cache — measure rate limit + latency in real use; add conditional ETag cache when needed.
  • No webhooks — when desire for "live PR changes during review" emerges, reintroduce webhooks (smee.io for dev, public URL for prod).
  • Permissive authz — UserRepoPermission cache table built but not consulted. Tighten when multi-tenant.
