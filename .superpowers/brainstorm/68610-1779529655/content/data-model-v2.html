What changed vs v1

  • New aggregate 0: Identity & Authz. User table linked to github login. UserRepoPermission cache for authz.
  • Workspace: worktree_path removed. No git operations needed for storyline.
  • Storyline: now a plain DB row (raw_json + updated_by_user_fk), not a parsed cache of a branch file. Storyline edits propagate via SSE immediately.
  • AIAnalysisDoc: ingested_by_user_fk added. Tracks who fed the doc in.
  • DraftReview / DraftComment / LocalAnnotation: user_fk added. Per-user scope enforced at query level + UNIQUE on (workspace, user) for in-flight drafts.
  • Outbox + SyncEvent: user_fk added. Audit log knows which app user triggered the action, even though all github calls go through admin PAT.

Authz rules (enforced by views + service layer)

op                              required permission
─────────────────────────────  ─────────────────────────────────────
view workspace                  UserRepoPermission.level >= read
post comment / submit review    UserRepoPermission.level >= read
read own drafts/annotations     always (filtered by user_fk)
read others' drafts/annotations FORBIDDEN (never returned)
edit storyline                  is PR author (user.github_login == pr.author_login)
                                 OR level >= maintain
ingest AI-doc                   same as storyline edit
close / reopen PR               level >= write  AND is PR author OR level >= maintain
merge PR                        level >= write  (further gated by github branch protection)

What still does NOT live in the schema

  • Full file content (fetch on demand via github API).
  • Per-line blame.
  • Organization / team mirroring (authz derived live from github).
  • Cross-PR / stacked-PR links.
  • Branch protection / CODEOWNERS (fetched at merge time, not mirrored).
