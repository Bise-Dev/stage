Section 1b · Lifecycle ops + idempotency model

Outbox row = unit of intent + unit of idempotency

Lifecycle ops in scope (all from local UI)

Mutations (outbox-driven)
  • Comments: post · reply · edit · delete · react
  • Threads: resolve · unresolve
  • Review: draft batch → submit (APPROVE / REQUEST_CHANGES / COMMENT)
  • PR state: draft↔ready · close · reopen
  • Merge: squash / merge / rebase (gated)
  • Storyline: write + commit + push .local-review/storyline.json
Observability (read-only mirror)
  • Workflow runs per commit
  • Check runs per commit
  • Required-status-checks state
  • Mergeability (clean / dirty / unstable / blocked)
  • PR head SHA · base SHA · diff metadata
  • Reviewers · assignees · labels

Outbox row shape

Outbox {
  id                  UUIDv7        # intent identity
  workspace_id        FK
  action_type         str           # 'comment.post' | 'pr.close' | 'thread.resolve' | ...
  payload             json
  status              enum          # pending | in_flight | succeeded | failed | conflicted
  attempt_count       int
  last_error          text?
  github_response_ref str?          # github object id after success
  precondition_etag   str?          # captured at enqueue, used for If-Match
  enqueued_at         ts
  resolved_at         ts?
}

Worker drain rules

  1. Lock row: pending → in_flight (SQLite BEGIN IMMEDIATE).
  2. Precondition check: re-read mirror. If already in target state (e.g., pr.close on already-closed PR), mark succeeded with note. Idempotent no-op.
  3. Push to github (PyGithub / gh). Send If-Match with stored ETag when supported.
  4. Success: store github_response_ref, mark succeeded, update mirror, append sync_event, fire SSE.
  5. API failure: attempt_count++, exponential backoff. After N tries → failed.
  6. 409 / ETag mismatch: mark conflicted, surface to UI. Never auto-overwrite.

Inbound idempotency

Github webhook delivery_id stored in sync_event with UNIQUE constraint. Duplicate delivery → insert collision → debug log, no-op. At-least-once delivery, exactly-once effect.

What this buys

  • Worker can crash mid-action and retry safely
  • Network blip during pr.close → retry → no-op if already closed
  • Webhook redelivery storms ignored
  • Audit log (sync_event) shows the truth for "what actually got pushed to github"

What needs care

  • Github doesn't support Idempotency-Key on most write endpoints → mirror-state check is the only line of defense
  • "Already in target state" detection is per action_type → small dispatch table
  • Conflict UX needs design (next section's problem)
