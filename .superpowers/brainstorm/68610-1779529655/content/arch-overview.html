Component responsibilities

  • Webhook Receiver — public-facing endpoint (behind tunnel). Validates github signature. Translates payload to internal event. Updates mirror + appends to sync_event. Fires SSE to UI.
  • Outbound Action Service — entry point for any local→github mutation. Writes an Outbox row inside a DB transaction; worker drains.
  • Sync Engine — the rulebook for how mirror state changes (idempotent updates, conflict detection, audit log writes).
  • Reconciliation Poller — periodic safety net. Fetches PR state, compares mirror, repairs drift.
  • Git ops — subprocess wrappers for fetch / read storyline / commit / push. Sandboxed: never touches the user's working repo, uses a managed worktree per workspace.
  • REST + SSE — the only surface the UI sees. Read endpoints serve mirror data; write endpoints enqueue to Outbox; SSE streams sync events.

Three data flow paths

  • Inbound (github → local): Github → tunnel → Webhook Receiver → mirror update + audit + SSE → UI refresh.
  • Outbound (local → github): UI → REST POST → Outbox row → worker → PyGithub/gh → on success, update mirror + audit → SSE.
  • Reconciliation (drift repair): Cron → PyGithub fetch → diff vs mirror → patch deltas + audit → SSE if changes.
