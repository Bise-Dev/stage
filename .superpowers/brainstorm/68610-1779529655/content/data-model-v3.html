Section 2 (revised v3) · IntroComment + author-only storyline

Storyline edit = PR author identity only. Anyone can discuss intros via local threads.

New entity: IntroComment

IntroComment (
  id,
  storyline_file_fk,    # which storyline file's intro is being discussed
  user_fk,              # who posted (must have UserRepoPermission.level >= read)
  parent_fk?,           # for replies, threaded
  body,
  created_at,
  updated_at,
  deleted_at?,          # soft-delete (preserves thread)
  resolved_by_user_fk?, # PR author can mark resolved
  resolved_at?
)
  • Local only. Never syncs to github. Lives in DB.
  • Tool-native concept. Github has no equivalent — storyline + intros are a backend invention, so the conversation around them is too.
  • Threaded. parent_fk self-ref builds reply chains.
  • PR author resolves. Only the author can flip resolved — same identity rule as storyline edit.
  • SSE broadcast. New IntroComment fires to all workspace subscribers.

Tightened authz table

op                                    required
─────────────────────────────────  ────────────────────────────────
view workspace                        permission >= read
post github comment / submit review   permission >= read
post IntroComment / reply             permission >= read
read own drafts/annotations           always (filtered by user_fk)
read others' drafts/annotations       FORBIDDEN
edit/delete own IntroComment          self only (same user_fk)
edit/delete others' IntroComment      FORBIDDEN
edit Storyline / StorylineFile        is PR author  (github_login == pr.author_login)
ingest AIAnalysisDoc                  is PR author
resolve IntroComment thread           is PR author
close / reopen PR                     permission >= write
merge PR                              permission >= write (+ github branch protection)

UX implications

  • UI shows a thread icon next to each intro that has IntroComments.
  • Author sees "N unresolved intro threads" as part of workspace dashboard.
  • Reviewers can reference an intro by anchor when posting actual github comments (e.g., "see intro thread on file X").
  • When storyline file ordering changes, IntroComment threads follow their storyline_file_fk — they don't break.
  • If author DELETES a file from storyline (or file removed from diff after force-push), its IntroComment thread is orphaned. Two options to decide later: hide / archive / soft-delete.
