# Branch actions are one shared menu; every branch name is an action surface

Status: accepted — supersedes the read-only scope note in `BranchGraph` (v6-light L6)

The branch action menu was built for one place: the chevron at the end of a `BranchTable` row. Branch names appear in four places, though — table rows, the graph's rail list, the graph's inline branch-tip chips, and (as a title fallback only) the GitHub-only rows. We decided that **a branch name is an action surface wherever it appears, and there is exactly one menu behind all of them**: a `BranchMenuProvider` at the overview level holds the rows and the action callbacks, renders a single menu instance, and every trigger site is one `openAt(event, branchName)` call. Right-click opens it where the row *is* the branch (a table row, a rail row) or on the chip itself; a hover-revealed chevron mirrors the table's affordance on rail rows so the menu is discoverable and keyboard-reachable in both views. Per-surface menus were rejected: three copies of the name→row lookup and three copies of the dismiss behaviour is exactly how two views come to disagree about what a branch can do.

Two consequences worth stating, because both look wrong in isolation:

- **The graph is no longer read-only.** L6 deliberately scoped it to "clicking a row highlights it locally and drives nothing else". A branch in the rail is the same branch as the one in the table, and offering the action there is the whole point; the read-only note is superseded rather than quietly contradicted. Nothing destructive rides on the gesture — the switch keeps its ADR-0027 command-listing confirmation, so a mis-aimed right-click cannot mutate anything. (The Storyline and Discard-review entries are commented out with the review surface, #144; they come back by uncommenting, alongside the entries in `branchMenuEntries`.)
- **The overview always fetches all rows.** The lookup must be total: every local branch has an `OverviewRow` (`overview.rs` sweeps the remainder), but archived rows were dropped in Rust, and a merged PR whose branch still exists locally is the ordinary case — that branch would show in the rail with no row behind it. `include_archived` is now always `true` and "Show archived" is a client-side view filter, which is what `commands.rs` already claimed it was ("a *view* filter — the snapshot always carries all"). A lookup miss is therefore a real invariant violation and fails loud.

The menu also gains a group that is always live (copy branch name, reveal worktree, open PR), so no branch produces an empty menu and no right-click is ever inert — which retires the `any` flag that gated the chevron and puts one on every table row, including the default branch.
